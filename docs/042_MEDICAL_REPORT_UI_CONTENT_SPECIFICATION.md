# LungEvidence Medical Report UI Content Specification

**Version:** 1.0
**Status:** Development Ready
**Last Updated:** 2026-08-03
**Classification:** Product Design Blueprint

---

## 1. Overview

### Purpose

定义患者端医学报告的：

- 页面结构
- 内容层级
- 表达规范
- 风险沟通方式

### 背景

很多健康产品失败不是因为医学错误，而是因为：

- 信息太专业，患者无法理解
- 风险表达制造恐慌
- 把统计结果误认为个人命运
- 用户看完反而更焦虑

**LungEvidence 的报告设计原则：先帮助患者理解，再提供医学深度。**

---

## 2. Report Design Principle

### 三层信息架构（Three Layers）

```
第一层：Patient Understanding（普通患者理解）
    例："你的肺癌属于早期阶段，目前已完成手术切除。"
        ↓
第二层：Medical Explanation（医学解释）
    例："根据AJCC第8版分期标准，你的浸润成分符合T1a范围。"
        ↓
第三层：Research Evidence（研究证据）
    例："相关研究显示……"
```

每一节内容都遵循这个层级，用户可以选择阅读深度。

---

## 3. Report Page Architecture

报告整体由六个部分组成：

```
1. Case Summary       — 我的病例概况
2. Stage Explanation  — 我的分期如何理解
3. Feature Analysis   — 为什么是这个分期？
4. Evidence Matching  — 你的病例特点
5. Follow-up Understanding — 如何理解未来随访
6. References         — 引用文献
```

---

## 4. Section 1: 我的病例概况（Case Summary）

### 目标

让患者第一眼知道："系统理解我的情况"。

### 展示内容

| 字段 | 示例 |
|------|------|
| 疾病 | 肺腺癌 |
| 位置 | 右肺上叶 |
| 治疗 | 手术切除 |
| 当前阶段 | 术后随访 |

### 设计规范

**避免第一屏出现"复发风险"等字样。**

第一屏的核心目标是建立信任感，让患者感受到：系统真的理解了我的情况。

---

## 5. Section 2: 我的分期如何理解（Stage Explanation）

### 展示示例

```
Stage IA1
```

**普通版解释：**
代表肿瘤浸润范围较小，同时没有发现淋巴结转移。

**医学版解释：**
pT1aN0M0 — AJCC 8th Edition

### 交互设计

- 默认显示普通版
- 点击"查看医学详情"展开医学版
- 提供"为什么是这个分期？"跳转到 Section 3

---

## 6. Section 3: 为什么是这个分期？（Feature Analysis）

这是非常重要的教育模块。

### 展示依据示例

**用户提供：CT 大小 29mm**

**系统解释：**

```
影像大小：29mm
    ↓
但肺癌分期主要参考：病理浸润成分
    ↓
你的浸润成分：< 10mm
    ↓
因此符合 T1a 范围（Stage IA1）
```

### 设计要点

- 用可视化箭头流程展示决策路径
- 每一步标注依据来源（AJCC 8th Edition）
- 避免直接给出结论，展示推导过程

---

## 7. Section 4: 你的病例特点（Evidence Matching）

采用卡片形式展示两类因素。

### 7.1 有利因素卡片

**名称：** 研究中通常与较好结果相关的因素

（**不要叫"好消息"**）

```
✓ N0 — 未发现淋巴结转移
✓ 无胸膜侵犯
✓ STAS 阴性
```

### 7.2 关注因素卡片

**名称：** 研究中被持续关注的因素

（**不要用红色警告**）

```
• 微乳头成分
• STAS 阳性
• 血管侵犯
```

**如果没有关注因素，显示：**
> 当前资料中未发现这些因素。

---

## 8. Section 5: 你的病例与哪些研究接近？

这是 LungEvidence 的核心差异化功能。

### 相似研究人群展示

```
相似研究人群：
✓ Stage IA
✓ 肺腺癌
✓ 手术切除
✓ N0
```

**重要：不要直接显示"你属于 95% 生存"。**

统计数字需要配合完整解释才能呈现，否则容易被误读为个人预测。

## 9. Evidence Card Design

每个研究用卡片展示：

```
┌─────────────────────────────────────┐
│  Ten-Year Follow-Up Study           │
│                                     │
│  研究对象：Stage IA NSCLC           │
│  随访时间：10 年                    │
│  样本量：3,271 例                   │
│                                     │
│  主要发现：[摘要]                   │
│                                     │
│  与你的关联：高度相关 ████████░░   │
│  证据强度：High                     │
│                                     │
│  [查看详情]  [原始论文]             │
└─────────────────────────────────────┘
```

---

## 10. Evidence Confidence（证据强度）

| 等级 | 标准 | 标识 |
|------|------|------|
| **High** | 多中心 / 长期随访 / 结论一致 | 🟢 |
| **Moderate** | 单中心或部分支持 | 🟡 |
| **Limited** | 研究不足或结论有争议 | 🟠 |

---

## 11. Section 6: 如何理解未来随访

### 核心目标：减少焦虑

**错误表达：**
> ❌ 注意复发风险。

**正确表达：**
> ✅ 手术后随访是早期肺癌管理的重要组成部分。

### 时间线展示

```
手术
 ↓
定期影像复查（每 3–6 个月）
 ↓
长期健康管理
```

---

## 12. AI 辅助解释框（AI Explanation Box）

### 设计风格：类似医生解释

**标题：** AI 辅助解释

**内容规范：**
- 必须使用短句
- 禁止绝对化表述

**示例：**
> 从目前提供的信息看，你的病例属于早期、无淋巴结转移的肺腺癌。多个研究关注的因素中，目前没有发现部分高风险病理特征。

**下方显示依据：**
```
Based on:
• 3 studies
• AJCC guideline
```

---

## 13. Ask AI Button（继续提问）

允许用户基于报告继续提问。

**示例问题：**
> "为什么 CT 2.9cm 但不是 IA3？"

**系统行为：**
- AI 调用当前 Case Context
- 仅基于 Evidence 回答
- 不得超出已有数据范围推断

---

## 14. Language Style Rules

### 禁止用词

| 禁止 | 原因 |
|------|------|
| ❌ 危险 | 制造恐慌 |
| ❌ 严重 | 绝对化 |
| ❌ 晚期可能 | 误导 |
| ❌ 一定 / 保证 | 超出证据范围 |

### 推荐用词

| 推荐 | 说明 |
|------|------|
| ✅ 研究关注 | 客观表达 |
| ✅ 需要随访 | 行动导向 |
| ✅ 目前信息显示 | 有限度 |
| ✅ 相关研究中 | 群体数据 |

---

## 15. Uncertainty Display

医学必须展示不确定性。

每个统计数字旁必须注明：

> 目前研究结果主要来自群体数据，不能完全预测个人情况。

## 19. Acceptance Criteria

用户在输入病例后，能够：

- [ ] 理解自己属于什么阶段
- [ ] 理解为什么这样分类
- [ ] 了解哪些因素影响研究结果
- [ ] 理解未来为什么需要随访
- [ ] 不会因为报告而产生不必要的恐慌
